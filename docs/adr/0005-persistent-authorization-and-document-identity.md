# Persist picker-authorized folders and keep document identity stable

The index must survive a restart, but the webview must never gain path access. Folio stores the folders that the user chose in the native picker and can reopen them by workspace id alone. Reopening is refused if the folder has gone, lost permission or now resolves elsewhere. A workspace is currently one active folder at a time; searching several folders together is deferred. Documents get opaque ids that survive renames and moves approved in Folio, so history and relationships stay attached. A rename outside Folio appears as a removal plus a new document, and the content hash still connects the two. Changes made outside Folio are detected when the folder is scanned or refreshed, not by a live watcher. If re-extracting a changed file fails, the previous index entries stay in place and the document is marked stale rather than silently dropped.
